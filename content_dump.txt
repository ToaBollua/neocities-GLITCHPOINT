<title>GLITCHPOINT // [GUIDE] Kotlin vs Java</title>
<h1>[GUIDE] Kotlin: Why Java is Being Left Behind</h1>
<p><a href="index.html"><< RETURN TO MAIN HUB</a></p>
AUTHOR:</strong> ToaBollua | <strong>DATE:</strong> Current Log | <strong>TAGS:</strong> Android, Backend, JVM
<p>To the university cadets and external developers still using Java in the 21st century: it is time to upgrade your tech stack. <em>Boilerplate</em> (repetitive and verbose code) is not a badge of honor; it is an insult to intelligence and operational efficiency.</p>
<h3>1. Default Immutability (val vs var)</h3>
<p>In Kotlin, you are forced to think about the mutability of your data from second zero.</p>
<li><span class="highlight">val</span> (Value): It is immutable. Once assigned, it cannot change. It is the equivalent of <code>final</code> in Java, but clean.</li>
<li><span class="highlight">var</span> (Variable): It is mutable. It should only be used if the data needs to be transformed.</li>
<p>Making your variables <code>val</code> prevents 90% of race conditions in multi-threaded architectures. Less mutability = Less entropy.</p>
<h3>2. The Eradication of the "Billion Dollar Mistake"</h3>
<p>The <code>NullPointerException</code> has crashed more systems than any DDoS attack. Kotlin eliminates it at the compiler level.</p>
<p>If you want to access a variable that could be null, Kotlin forces you to handle the error using safe call operators like <code>?.</code> or the Elvis operator <code>?:</code>.</p>

<title>GLITCHPOINT // [ARCHITECTURE] Multi-Cloud & Edge</title>
<h1>[ARCHITECTURE] Multi-Cloud and Edge Computing</h1>
<p><a href="index.html"><< RETURN TO MAIN HUB</a></p>
AUTHOR:</strong> ToaBollua | <strong>DATE:</strong> Current Log | <strong>TAGS:</strong> AWS, Azure, EdgeAI, Hardware
<p>Attention operatives: relying on a single cloud provider is a Single Point of Failure (SPOF) risk. The natural evolution of critical systems is a <strong>Multi-Cloud Architecture</strong> coupled with <strong>Edge Computing</strong>.</p>
<h3>1. Edge Computing in AI Cameras</h3>
<p>It makes no sense to send terabytes of raw video to the cloud for an AI to analyze and return a response with massive latency. Processing must occur at the "edge".</p>
<li>Modern cameras must possess local NPUs (Neural Processing Units).</li>
<li>The device captures, executes the computer vision model locally, and <strong>only sends the processed telemetry</strong> to the central network (e.g., "Anomaly detected in the perimeter").</li>
<li>This reduces bandwidth consumption by 95% and allows for tactical operations without an internet connection.</li>
<h3>2. Disaster Recovery: AWS / Azure Synchronization</h3>
<p>For the core infrastructure, <em>Disaster Recovery</em> demands cross-redundancy.</p>
<p>If the main cluster resides on <strong>AWS (Amazon)</strong>, database backups (PostgreSQL/Vectorial) must be replicated asynchronously to a passive cluster on <strong>Microsoft Azure</strong>. If an Amazon data center collapses, DNS traffic is automatically routed to Azure, keeping the entity alive.</p>
